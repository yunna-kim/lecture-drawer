# 강의서랍

> tiro, plaud 노트가 없을 때 쓸 수 있는 OS, 번거롭게 설정하는 과정을 다 생략하기 위해서 애썼다.

스폰지클럽 크루가 휴대폰으로 녹음한 강의·모임을 자기 PC에서 글로 바꾸고, 필요하면 AI로 정리해 Obsidian에 모아두는 작업 도구입니다. 여기서 OS는 녹음부터 복습까지 이어주는 작업 시스템이라는 뜻입니다. Windows를 바꾸는 운영체제가 아닙니다.

녹음 앱은 지금 쓰는 것을 그대로 쓰세요. 강의서랍은 녹음이 끝난 파일부터 맡습니다. 처음 한 번 폴더와 전사 모델을 준비하면, 평소에는 실행하고 필요한 녹음을 고르는 흐름으로 쓰도록 만들었습니다.

## 먼저 내 경로 고르기

| 내 상황 | 따라갈 순서 |
|---|---|
| NAS가 없다. PC에서 먼저 써보고 싶다 | **1 → 2 → A → 4 → 5** |
| NAS가 있다. 휴대폰 녹음을 집에서 자동 백업하고 싶다 | **1 → 2 → B → 4 → 5** |
| 제목·요약도 만들고 싶다 | 위 경로를 끝낸 뒤 **6** |
| 왜 이런 기능과 설정이 있는지 궁금하다 | **7** |
| 오류가 났다 | **8** |

두 경로 모두 결과는 PC에서 지정한 노트 폴더에 저장합니다. 그 폴더를 Obsidian 보관함 안에 두면 Obsidian에서도 바로 읽을 수 있습니다.

```text
A. 휴대폰 녹음 → USB 등으로 PC 녹음 폴더에 복사 ─┐
                                               ├→ 내가 선택 → 로컬 전사 → 노트 폴더 → Obsidian
B. 휴대폰 녹음 → FolderSync → NAS 녹음 폴더 ──────┘                  └→ 선택한 AI로 제목·정리
```

**처음에는 개인정보 없는 20~30초 테스트 녹음 하나로 끝까지 해보세요.** PC 경로로 성공한 뒤 NAS 자동 백업이나 AI 정리를 추가해도 됩니다.

## 1. 무엇이 필요한가요?

| 준비물 | 하는 일 | 꼭 필요한가요? |
|---|---|---|
| Windows PC | 강의서랍 실행·음성 전사 | 이 안내의 기본 환경 |
| 녹음 파일 | 글로 바꿀 음성 | 필요. 녹음을 끝낸 파일 사용 |
| Python 3.12 64비트 | 프로그램 실행 | 첫 설치에 필요 |
| FFmpeg | 음성을 읽고 구간으로 나누기 | 첫 설치에 필요 |
| 전사 모델 | PC에서 소리를 글로 바꾸기 | 설치 중 한 번 다운로드 |
| Obsidian | 저장된 노트를 읽고 연결하기 | 권장. 없어도 Markdown 파일 저장 가능 |
| NAS·FolderSync | 휴대폰 녹음을 자동 백업 | B 경로에서만 필요 |
| Claude 또는 OpenAI API 키 | 제목·요약 생성 | 선택. 전사 원문만 저장할 때는 불필요 |

전사는 PC에서 Whisper turbo로 처리합니다. 기본 설치는 CPU 방식이라 NVIDIA 그래픽카드가 없어도 시작할 수 있습니다. 속도는 PC와 음성 길이에 따라 달라집니다. 처음에는 짧은 녹음으로 확인하세요. 모델은 약 1.62GB이고, 실행 환경·작업 중 파일까지 저장할 여유 공간이 필요합니다. [모델 배포처](https://huggingface.co/dropbox-dash/faster-whisper-large-v3-turbo)

Windows용 실행 파일을 제공합니다. Mac·Linux의 설치와 실제 음성 처리는 이 공개본의 검증 범위에 포함하지 않았습니다.

## 2. 공통 준비: 프로그램과 Obsidian

### 2-1. 강의서랍 내려받기

1. 이 GitHub 저장소에서 초록색 **Code**를 누릅니다. GitHub는 프로그램 파일을 보관하고 공유하는 사이트입니다.
2. **Download ZIP**을 누릅니다.
3. 내려받은 ZIP을 마우스 오른쪽 버튼으로 누르고 **압축 풀기**를 선택합니다.
4. 풀린 폴더를 `문서` 같은 찾기 쉬운 곳으로 옮깁니다. ZIP 안에서 바로 실행하지 마세요.
5. 그 폴더 안에 `Install.cmd`, `Start.cmd`, `README.md`가 보이면 준비됐습니다.

Git이나 GitHub 계정 없이도 ZIP으로 받을 수 있습니다. Git은 변경 이력을 기록하는 도구인데, 사용만 할 때는 직접 다룰 필요가 없습니다.

### 2-2. Python 준비하기

1. [Python 공식 다운로드](https://www.python.org/downloads/)에서 **Python 3.12 Windows installer (64-bit)**를 설치합니다.
2. 설치 화면에 **Add python.exe to PATH**가 있으면 체크합니다. 다른 프로그램이 Python을 찾을 수 있게 하는 설정입니다.
3. 설치가 끝나면 열어둔 터미널을 닫았다가 다시 엽니다.
4. 확인하고 싶으면 시작 메뉴에서 `터미널`을 열고 아래 한 줄을 입력합니다.

```powershell
py -3.12 --version
```

`Python 3.12...`가 나오면 됩니다. 다른 Python이 이미 있어도 기존 것을 지울 필요는 없습니다. 강의서랍은 자신의 폴더 안 `.venv`에 실행 환경을 따로 만듭니다.

### 2-3. FFmpeg 준비하기

FFmpeg는 음성 파일을 읽는 도구입니다. 이미 설치돼 있으면 다시 설치하지 않아도 됩니다.

1. 시작 메뉴에서 **터미널** 또는 **PowerShell**을 엽니다.
2. 다음 한 줄을 입력하고 Enter를 누릅니다.

```powershell
winget install --id Gyan.FFmpeg --exact
```

3. Windows 패키지 설치 도구의 안내를 확인해 설치합니다. `winget`을 찾을 수 없으면 Microsoft Store에서 Microsoft의 **앱 설치 관리자**를 확인하거나 [FFmpeg 공식 다운로드 안내](https://ffmpeg.org/download.html)를 따릅니다.
4. 설치가 끝나면 터미널 창을 닫고 다시 엽니다.
5. 다음 두 줄을 한 줄씩 입력합니다.

```powershell
ffmpeg -version
ffprobe -version
```

두 명령에서 버전이 나오면 됩니다. 둘 중 하나를 찾을 수 없으면 아직 강의서랍 설치를 진행하지 말고 아래 오류 표를 확인하세요.

### 2-4. Obsidian에 노트가 들어올 자리 만들기

1. [Obsidian 공식 사이트](https://obsidian.md/)에서 PC용 앱을 설치합니다.
2. 처음 쓰면 **새 보관함 만들기 / Create new vault**를 선택합니다. 보관함은 노트를 담는 실제 폴더입니다.
3. 이름은 예를 들어 `내 공부노트`로 정합니다. 기존 보관함이 있으면 그것을 써도 됩니다.
4. 그 보관함 안에 `강의서랍` 폴더를 만듭니다.
5. Windows 파일 탐색기에서 `강의서랍` 폴더를 열고, 위쪽 주소 표시줄을 눌러 주소를 복사합니다.

예시: `C:\StudyNotes\강의서랍`

이 주소를 나중에 **노트 폴더 주소**에 넣습니다. 예시 주소를 그대로 넣는 것이 아니라 **본인 PC의 실제 폴더 주소**를 넣으세요. 다른 보관함의 파일을 복사해 가져올 필요는 없습니다. [Obsidian 보관함 공식 안내](https://help.obsidian.md/manage-vaults)

Obsidian을 당장 쓰지 않으면 별도 노트 폴더를 골라도 됩니다. 나중에 Obsidian에서 **폴더를 보관함으로 열기 / Open folder as vault**로 그 폴더를 열 수 있습니다.

## A. NAS 없이 PC 폴더로 시작하기

### A-1. 녹음 폴더 만들기

1. Windows 파일 탐색기에서 `문서`를 엽니다.
2. `녹음보관`이라는 새 폴더를 만듭니다.
3. 휴대폰 녹음 앱에서 테스트 녹음을 하고 **종료·저장**합니다.
4. USB 케이블로 휴대폰을 연결합니다. 휴대폰에서 필요하면 **파일 전송**을 선택합니다.
5. 녹음 앱의 저장 위치에서 테스트 파일을 찾아 PC의 `녹음보관`으로 **복사**합니다. 녹음 앱의 공유·내보내기로 음성 파일을 PC에 가져와도 됩니다.
6. PC에 복사된 파일을 재생해 끝까지 있는지 확인합니다.
7. `녹음보관` 폴더의 주소를 복사합니다.

이지 레코더를 쓴다면 `Recordings/Easy Voice Recorder`가 후보입니다. 앱 설정과 휴대폰에 따라 달라지므로 실제 저장 위치를 확인하세요.

### A-2. 설치 화면에서 두 주소 넣기

1. 압축을 풀어둔 강의서랍 폴더에서 **Install.cmd**를 두 번 누릅니다.
2. 필요한 Python 라이브러리가 설치될 때까지 기다립니다. 검은 창은 작업 진행 창이니 닫지 마세요.
3. **녹음 폴더 주소**가 나오면 방금 만든 `녹음보관`의 주소를 붙여넣고 Enter를 누릅니다.
4. **노트 폴더 주소**에는 2-4에서 준비한 Obsidian 안 `강의서랍`의 주소를 넣습니다.
5. 전사 모델 다운로드 안내가 나오면 준비됐을 때 아무 키나 누릅니다. 취소하려면 Ctrl+C를 누릅니다.
6. 모델 다운로드와 등록이 끝나 **설치 완료**가 나오면 설치 창을 닫습니다.
7. 아래 **4. 첫 전사**로 갑니다.

PC 경로에는 NAS 계정·SMB·FolderSync 설정이 필요 없습니다. 새 녹음이 생길 때 PC 녹음 폴더로 가져오는 단계만 직접 합니다.

## B. NAS로 자동 백업하며 쓰기

NAS는 집이나 사무실 네트워크에 붙여 쓰는 저장 장치입니다. 이 경로는 **휴대폰 → NAS로 원음 복사**, **PC → NAS의 음성 읽기**, **PC → Obsidian에 노트 저장**으로 나뉩니다.

### B-1. 먼저 PC에서 NAS 폴더 열기

1. PC와 휴대폰을 NAS에 접근할 수 있는 Wi-Fi·네트워크에 연결합니다.
2. Windows 파일 탐색기 주소 표시줄에 본인 NAS 공유 폴더 주소를 넣습니다.
3. 계정과 비밀번호가 필요하면 Windows에서 본인의 NAS 계정으로 접속합니다.
4. 공유 폴더 안에 `Recordings` 같은 녹음 보관 폴더를 만듭니다.
5. 테스트 파일을 하나 넣고 열 수 있는지 확인합니다.
6. 이 폴더의 주소를 복사합니다. 이것이 강의서랍의 **녹음 폴더 주소**입니다.

형식 예시: `\\NAS이름\공유폴더\Recordings`

강의서랍에는 NAS 비밀번호를 넣지 않습니다. **파일 탐색기에서 먼저 열리는 상태**를 만드는 것이 순서입니다. 앱이 읽을 수 있게 권한을 주고, 원음 이름 변경 기능까지 쓰려면 해당 파일의 이름 변경 권한도 확인해야 합니다.

### B-2. 휴대폰에 FolderSync 설치하기

1. Android 휴대폰의 Play 스토어를 엽니다.
2. **Tacit Dynamics**의 **FolderSync**를 설치합니다.
3. 녹음 폴더를 읽는 데 필요한 파일 접근 권한을 확인합니다.
4. 바로 결제하거나 고급 Automation 기능부터 켤 필요는 없습니다. 먼저 현재 앱에서 기본 폴더 쌍과 예약 설정이 가능한지 봅니다.

이 안내는 Android FolderSync 기준입니다. iPhone에서 같은 설정을 그대로 적용하는 안내는 아닙니다.

### B-3. FolderSync에 NAS 계정 등록하기

1. FolderSync에서 **계정 / Accounts → 추가 / +**를 누릅니다.
2. **SMB2/SMB3** 계정을 선택합니다. 집 네트워크의 공유 폴더에 접근하는 방식입니다.
3. 아래 칸을 **본인 NAS 정보**로 채웁니다.

| 입력 칸 | 넣을 내용 |
|---|---|
| 연결 이름 | 내가 알아볼 이름. 예: 집 NAS |
| 서버 주소 | NAS의 IP 주소 또는 이름. 전체 폴더 경로를 넣지 않음 |
| 포트 | 특별히 바꾸지 않았다면 기본 445 |
| SMB 공유 이름 | NAS에서 만든 공유 폴더 이름 |
| 사용자 이름·비밀번호 | 해당 공유 폴더에 접근할 본인 NAS 계정 |
| 도메인 | 별도 설정이 없으면 비움 |

4. **연결 테스트**를 누르고 성공하면 저장합니다.
5. 실패하면 Wi-Fi·NAS 전원·계정·공유 폴더 접근권한부터 확인합니다. 비밀번호를 채팅·README·GitHub에 붙이지 마세요.

NAS 관리자 화면의 공유 폴더 이름과 그 안의 하위 폴더는 다릅니다. 서버 주소 칸에 `\\NAS이름\공유폴더\Recordings` 전체를 넣거나, 공유 이름을 두 번 넣지 않도록 확인하세요. [SMB 계정 공식 안내](https://foldersync.io/docs/help/fileprotocols/)

### B-4. 녹음 폴더 두 개 연결하기

1. **폴더 쌍 / FolderPairs → 추가**를 누릅니다.
2. 이름은 `휴대폰 녹음 백업`처럼 적습니다.
3. **왼쪽 폴더**에는 휴대폰 녹음 앱이 실제로 저장하는 폴더를 고릅니다.
4. **오른쪽 계정**에는 방금 만든 NAS 계정을 고릅니다.
5. **오른쪽 폴더**에는 NAS의 녹음 보관 폴더를 고릅니다.
6. 방향은 **오른쪽 폴더로 / To right folder**로 정합니다. 구버전에서는 **원격 폴더로 / To remote folder**일 수 있습니다.
7. 화면에서 **출발지가 휴대폰이고 도착지가 NAS인지** 다시 확인합니다.

왜 한쪽 방향인가요? 휴대폰에서 지우거나 이름을 바꾼 일이 NAS의 보관 원음까지 바꾸는 것을 줄이기 위해서입니다. NAS에서 바꾼 이름도 휴대폰으로 돌아가지 않습니다. [폴더 쌍 공식 안내](https://foldersync.io/docs/help/v2/folderpairs/)

### B-5. 원음 보존 설정 확인하기

| 설정 | 처음 쓸 때 | 이유 |
|---|---|---|
| 삭제 동기화 / Sync deletions | **끔** | 휴대폰에서 지워도 NAS에 보관 |
| 이동 후 원본 삭제 / Move files to target folder | **끔** | 휴대폰 원본도 유지 |
| 기존 파일 덮어쓰기 / Overwrite old files | **Never / 안 함** 권장 | 같은 이름 충돌 때 임의 교체 방지 |
| 충돌 처리 | **건너뛰고 확인** | 서로 바뀐 파일을 자동 결정하지 않음 |
| 임시 이름으로 업로드 / Use temp-file scheme | **켬** | 복사가 끝난 뒤 최종 파일 이름으로 표시 |
| 원본 변경 시에만 다시 동기화 / Only resync source files if modified | **켬** | NAS에서 이름을 바꿔도 옛 이름으로 다시 복사되는 문제를 줄임 |
| 파일 크기 확인 비활성화 | **끔 유지** | 전송 확인을 끄지 않음 |
| 날짜별 새 폴더에 전체 복사 | **끔** | 예약마다 같은 원음 사본이 쌓이지 않게 함 |

하위 폴더·숨김 파일은 처음에는 필요한 녹음 폴더 범위만 선택하세요. 암호화된 콘텐츠 파일로 바꾸는 기능은 이 흐름에서 사용하지 않습니다. 전사 앱이 읽을 수 있는 일반 음성 파일이 필요합니다.

**‘원본 변경 시에만 다시 동기화’는 대상에서 지운 파일의 자동 복원도 막습니다.** NAS의 보관 원음을 실수로 지워도 다음 예약이 복원해줄 것이라고 기대하지 마세요. 중요한 원음은 별도의 보관 정책을 정하고 유지하세요. [FolderSync 설정 공식 안내](https://foldersync.io/docs/help/v2/folderpairsettings/)

### B-6. 집 Wi-Fi에서 예약 백업하기

1. 해당 폴더 쌍에서 **예약 / Scheduling**을 엽니다.
2. 예를 들어 **1시간 간격**으로 설정합니다. 원하는 주기를 고르면 됩니다.
3. **Wi-Fi만** 허용하고 모바일 데이터는 끕니다.
4. **허용 Wi-Fi 이름 / SSID**에 휴대폰에 표시되는 집 Wi-Fi 이름을 넣습니다.
5. 2.4GHz와 5GHz 이름이 다르면 실제 사용할 이름을 각각 확인합니다.
6. SSID를 읽기 위해 위치 권한이 필요하면 해당 앱의 안내를 확인합니다. 백그라운드 예약에는 백그라운드 위치 접근 조건도 확인합니다.
7. 예약을 저장하고 켜짐 상태인지 확인합니다.
8. 화면이 꺼진 상태에서 다음 예약도 성공하는지 확인합니다. 예약이 멈출 때만 FolderSync의 앱별 배터리 제한을 확인하세요.

집에 도착한 순간 복사되는 것이 아니라 **다음 예약 시간에** 복사될 수 있습니다. 수동 동기화가 된 것과 예약 동기화가 된 것은 따로 확인하세요. 현행 버전에서는 예약별 연결 조건과 수동 실행 조건이 다를 수 있습니다. [예약](https://foldersync.io/docs/help/v2/scheduling/), [연결 조건](https://foldersync.io/docs/help/v2/connection/), [권한](https://foldersync.io/docs/help/permissions/)

### B-7. 테스트 후 강의서랍 연결하기

1. 개인정보 없는 테스트 녹음을 종료·저장합니다.
2. FolderSync에서 해당 폴더 쌍을 **수동 동기화**합니다.
3. PC 파일 탐색기에서 NAS 파일이 생겼는지, 끝까지 재생되는지 확인합니다.
4. 테스트 파일에 한해서 휴대폰에서 지운 뒤에도 NAS에 남는지 확인합니다. 중요한 원음으로 삭제 시험을 하지 마세요.
5. 테스트 녹음을 하나 더 만들고, 화면을 끈 상태에서 **다음 예약으로** 복사되는지 봅니다.
6. 강의서랍 폴더의 **Install.cmd**를 실행합니다.
7. **녹음 폴더 주소**에 B-1에서 확인한 NAS 폴더를 넣습니다.
8. **노트 폴더 주소**에 Obsidian 안 `강의서랍`의 주소를 넣습니다.
9. 전사 모델 다운로드·등록을 마칩니다.

**백업 성공과 전사 시작은 별개입니다.** NAS에 들어온 모든 녹음이 자동으로 AI에 넘어가지 않습니다.

## 4. 첫 전사: 음성을 글로 바꾸기

1. **Start.cmd**를 두 번 누릅니다.
2. 브라우저에서 `http://127.0.0.1:8767`이 열립니다. 이 주소는 지금 PC의 프로그램 화면입니다.
3. 새로 들어온 녹음이 목록에 보일 때까지 기다립니다. 크기와 수정 시각이 안정됐는지 확인하는 시간이 있습니다.
4. 새 녹음은 기본적으로 **보류** 쪽에 있습니다. 전사할 테스트 파일만 **전사 예정에 추가**합니다.
5. 전사 예정에서 파일을 체크하고 **선택한 강의 전사하기**를 누릅니다.
6. 처음에는 정리 템플릿을 **전사 원문만**으로, **자동 제목은 끔**으로 둡니다. API 키 없이 전사부터 확인하는 순서입니다.
7. 필요하면 강좌명·회차를 적습니다. 전문용어·사람 이름·영어 약어는 **용어 힌트**에 넣습니다.
8. **전사하고 옵시디언에 저장**을 누릅니다.
9. **전사 작업** 탭에서 진행 상황을 봅니다. 여러 파일은 순서대로 처리합니다.
10. 완료되면 **전사·원음 확인**을 열고 시작·중간·끝을 들어봅니다. 숫자·고유명사·‘안 된다/된다’처럼 뜻이 뒤집히는 표현도 확인하세요.

일부만 다시 보고 싶으면 시작·끝 시간을 초로 지정해 **구간 전사**를 할 수 있습니다. 기존 전체 전사와 별도 작업으로 남습니다.

**평소 쓰는 순서:** 녹음 종료 → PC로 복사 또는 NAS 백업 확인 → Start.cmd → 필요한 파일만 선택 → 전사 → Obsidian에서 읽기.

## 5. Obsidian으로 들어온 결과 보기

1. 완료 작업에서 **옵시디언에서 열기**를 누릅니다.
2. 브라우저가 외부 앱 열기를 물으면 Obsidian을 확인하고 엽니다.
3. Obsidian 왼쪽 파일 목록의 `강의서랍` 폴더에도 새 `.md` 파일이 보이는지 확인합니다.
4. 노트 위에는 선택한 AI 정리가, **Original Content** 아래에는 전체 전사 원문이 들어갑니다. 원문만 선택했다면 AI 정리는 없습니다.
5. 시간표시를 보며 읽고, 원음 확인은 강의서랍 화면의 시간 버튼으로 합니다. 스크롤 중에는 미니 플레이어로 재생을 이어갈 수 있습니다.

별도 Obsidian 플러그인은 필요하지 않습니다. 강의서랍이 보관함 안에 Markdown 파일을 저장하기 때문에 보입니다. ‘옵시디언에서 열기’ 버튼은 Obsidian 전용 링크를 쓰며, Windows의 `.md` 기본 앱을 바꾸지 않습니다.

휴대폰 Obsidian에서도 읽으려면 **보관함 자체의 동기화는 별도로** 준비해야 합니다. 강의서랍에 저장됐다는 이유로 휴대폰까지 동기화됐다고 보지는 않습니다. 원음이 PC·집 NAS에만 있으면 휴대폰에서 원음 링크를 열지 못할 수 있습니다.

## 6. 선택: AI 제목·정리와 구독 API 크레딧 연결하기

전사는 PC의 Whisper가, 제목·정리는 따로 고른 AI가 맡습니다. **전사 원문만 + 자동 제목 끔**이면 외부 정리 AI에 전사 텍스트를 보내지 않습니다. API 정리를 선택하면 전사 텍스트와 제목·용어 힌트·정리 요청이 선택한 제공자로 전송됩니다. 원음 파일을 그 API에 업로드하는 방식은 아닙니다.

API 키는 내 프로그램이 내 AI 계정에 요청할 수 있게 하는 비밀 열쇠입니다. 아래 입력 창에서만 넣으세요. 이 저장소나 다른 사람의 키를 함께 쓰지 않습니다.

### 6-1. 구독에 포함된 API 혜택부터 확인하기

**2026-11-16 공식 안내 확인 기준**입니다. 혜택을 받아서 API로 정리를 맡기려는 것이지, 강의서랍 사용에 고가 구독이 필수인 것은 아닙니다. 이미 가입한 크루는 본인 계정에서 제공 여부를 확인하세요.

| 구독 | 확인된 API 혜택 | 신청 위치 |
|---|---|---|
| Claude Max·Ultra·Team | Max 월 $100, Ultra 월 $200. Team은 좌석별 합산·상한 적용 | Claude 설정 → Billing → API credits → 조직 연결 |
| ChatGPT Pro·Business | Pro 요금제·Business 좌석에 따른 API 크레딧 | ChatGPT 또는 API Platform의 Billing → API credits 혜택 신청 |

두 제공자 모두 대상 구독의 가입 기간·소유권·API 조직 연결 조건을 확인해야 합니다. 신규 대상 구독은 7일 조건이 있습니다. 혜택의 만료와 갱신일은 본인 결제 주기와 계정 화면에서 확인하세요. API 크레딧이 대화형 Codex·Claude Code의 구독 사용 한도를 늘려주는 것은 아닙니다. [Claude 공식 안내](https://platform.claude.com/docs/en/about-claude/api-credits-for-subscribers), [OpenAI 공식 안내](https://developers.openai.com/api/docs/guides/chatgpt-api-credits)

### 6-2. Claude API 연결하기

1. [Claude](https://claude.ai/)에서 본인 계정으로 로그인합니다.
2. 대상 구독이면 **Settings → Billing → API credits**에서 **Link organization**을 선택합니다.
3. 크레딧을 받을 본인 Console 조직을 선택하거나 만듭니다. 조직은 API 사용과 비용을 묶는 계정 단위입니다.
4. [Claude Console 결제 화면](https://platform.claude.com/settings/billing)에서 크레딧과 만료일을 확인합니다.
5. 강의서랍용 workspace를 따로 만들고 사용할 금액 상한을 정합니다. 같은 조직의 다른 앱과 잔액은 공유할 수 있어도, 키와 관리 단위는 나누려는 설정입니다.
6. 해당 workspace에서 API key를 만듭니다. 키가 표시될 때 본인 PC에 안전하게 보관합니다.
7. 강의서랍 폴더 빈 곳을 마우스 오른쪽 버튼으로 눌러 **터미널에서 열기**를 선택합니다.
8. 다음을 실행합니다. `모델ID`는 Console의 모델 선택 목록에서 확인한 ID로 바꿉니다. 예를 들어 본인 계정에 `claude-opus-5-5`가 있으면 그 글자를 넣습니다. 모델에 따라 사용량과 비용이 달라집니다.

```powershell
.\.venv\Scripts\python.exe cli.py register-claude-api --model 모델ID
```

9. API 키 입력 안내가 나오면 붙여넣고 Enter를 누릅니다. 화면에 글자가 보이지 않아도 정상입니다.
10. 새 작업의 기본 정리 AI로 쓰려면 다음을 실행합니다.

```powershell
.\.venv\Scripts\python.exe cli.py use-note-ai claude-api
```

11. 화면을 새로고침하고 **새 요청 정리 AI: Claude API**를 확인합니다. 첫 요청은 짧은 테스트 전사로 정리를 확인하고 Console 사용량도 봅니다.

강의서랍은 전용 로컬 키 파일을 읽습니다. `ANTHROPIC_API_KEY`를 PC 전체 환경변수로 등록하지 않아도 됩니다. 다른 Claude Code 작업의 인증·과금 경로와 섞이지 않게 하려는 선택입니다.

### 6-3. OpenAI API 연결하기

1. 대상 ChatGPT 구독 계정으로 [API Platform](https://platform.openai.com/)에 로그인합니다. 조직 연결에는 구독과 같은 이메일·소유권 조건을 확인합니다.
2. **Billing**의 API credits 혜택을 신청하고 크레딧을 받을 조직을 확인합니다.
3. 결제 화면에 크레딧이 들어왔는지 확인합니다.
4. 강의서랍용 프로젝트에서 API key를 만듭니다. 이 프로젝트가 크레딧을 받은 조직에 속하는지 확인합니다.
5. 강의서랍 폴더의 터미널에서 실행합니다. `모델ID`는 API Platform의 모델 목록에서 본인 계정에 허용된 Responses API 모델 ID를 확인해 바꿉니다. 모델 이름을 강의서랍이 임의로 고르거나 더 비싼 모델로 바꾸지는 않습니다.

```powershell
.\.venv\Scripts\python.exe cli.py register-openai-api --model 모델ID
```

6. 키를 입력한 뒤 다음을 실행합니다.

```powershell
.\.venv\Scripts\python.exe cli.py use-note-ai openai-api
```

7. 새로고침 후 **새 요청 정리 AI: OpenAI API**를 확인합니다. 짧은 테스트 정리와 API 사용량 화면을 확인합니다.

여기서는 강의서랍이 OpenAI API를 직접 부릅니다. Codex를 API 키로 실행하는 기능은 아닙니다. 크레딧을 받은 조직의 프로젝트 키를 쓰는 것이 연결의 핵심입니다. [OpenAI 크레딧 적용 범위](https://developers.openai.com/api/docs/guides/chatgpt-api-credits)

### 6-4. 정리 템플릿 고르기

1. 새 전사를 요청할 때 **강의·세미나** 또는 **회의** 템플릿을 고릅니다.
2. **프롬프트**를 펼치면 AI에게 시킬 정리 형식을 볼 수 있습니다. 필요한 부분만 이번 요청에 맞게 고칩니다.
3. 자동 제목을 원하면 켭니다. 강좌명·회차를 알고 있으면 입력해 두세요. AI가 알아서 추측하게 두지 않기 위한 항목입니다.
4. 요청 창에서 **제목·정리 AI**가 원하는 제공자인지 확인합니다.
5. 전사와 정리를 실행합니다. 결과 위의 AI 정리와 아래의 전체 원문을 구분해 읽습니다.

이미 등록된 작업은 등록 당시 AI와 요청을 유지합니다. 기본 AI를 바꿔도 과거 요청을 몰래 다른 제공자로 보내지 않습니다. 한도가 막혀도 다른 유료 AI로 자동 전환하지 않습니다.

### 6-5. 비용과 잔액을 보는 방법

| 단계 | 쓰는 자원 |
|---|---|
| PC·NAS 파일 목록 확인 | PC·저장 장치 |
| Whisper 전사 | PC CPU 또는 설정한 GPU·전력·저장 공간 |
| Claude·OpenAI API 제목·정리 | 해당 API 조직의 크레딧·과금·한도 |
| Obsidian에 파일 저장·기존 원문 읽기 | PC·보관함 저장 공간 |

정리 API로 분리하면 그 작업을 대화형 개발 도구로 직접 실행하는 대신 API 쪽에서 처리할 수 있습니다. 개발 도구의 구독 한도 자체가 늘어나는 것으로 계산하지는 않습니다.

공개본은 다른 앱까지 포함한 실제 잔액을 알 수 없어 ‘남은 크레딧’을 임의로 표시하지 않습니다. 정확한 잔액·사용량·만료일은 각 Console에서 봅니다. 구독 혜택이 남아 있어도 구매 잔액·자동 충전 설정에 따라 청구가 이어질 수 있으므로, **조직의 자동 충전과 사용 한도도 함께 확인**하세요. 앱은 결제·충전을 실행하지 않습니다.

### 6-6. 외부 API 없이 정리하고 싶다면

기본은 원문 저장부터 사용하세요. 추가로 Ollama의 로컬 `qwen3.5:4b`를 설치·검토한 사용자는 다음처럼 등록할 수 있습니다. [Ollama 공식 안내](https://ollama.com/)

```powershell
.\.venv\Scripts\python.exe cli.py register-local-notes --model qwen3.5:4b --port 11434
.\.venv\Scripts\python.exe cli.py use-note-ai qwen-local
```

등록 명령이 모델을 설치해주지는 않습니다. 이 소형 모델의 정리는 강의 내용의 누락·추정 문제가 확인돼 기본값으로 두지 않았습니다. 생성 성공과 내용 품질을 따로 보고 원문과 검토하세요.

## 7. 왜 이렇게 만들었나요?

### ‘녹음했다’에서 ‘다시 읽는다’까지 연결하려고

녹음 파일이 있어도 이름이 모호하고 텍스트를 옮겨야 한다면 복습까지 여러 단계를 거칩니다. 그래서 기존 녹음 앱을 유지하면서 선택·전사·제목·정리·Obsidian 저장을 이어 붙였습니다. tiro·plaud 노트가 없는 크루도 자기 파일로 같은 흐름을 만들 수 있게 하려는 목적입니다.

### 백업은 넓게, 전사는 내가 고른 것만

휴대폰의 녹음이 모두 강의는 아닐 수 있습니다. 새 파일을 전부 자동 처리하면 원치 않는 내용까지 분석하거나 API로 보낼 수 있습니다. 그래서 **백업과 전사 승인**을 나누고 새 녹음은 **기본 보류**로 둡니다. 전사할 것만 예정에 올리는 방식입니다.

### 원음·전사 원문·AI 정리를 각각 남기려고

요약이 편해도 원래 어떤 말이었는지 확인할 수 있어야 합니다. 원음을 지우지 않고, 요약으로 전사 원문을 덮지 않으며, 시간표시로 원음에 돌아가게 했습니다. 문단마다 시간을 하나씩 붙이고 미니 플레이어를 둔 것도 읽고 듣는 작업을 덜 번거롭게 하려는 선택입니다.

### 실패한 자리에서 다시 시작하려고

긴 음성은 구간으로 나누고 완료 구간을 저장합니다. 연결이나 AI 한도에 문제가 생겨도 **같은 선택 작업 재시도**로 이미 끝난 전사를 재사용합니다. AI 응답도 먼저 보관해서 형식 오류만으로 자동 재생성하지 않습니다. 통신 중 끊긴 요청은 이미 사용량이 소비됐을 수 있어, 자동 반복 대신 사용자가 재시도를 결정하게 했습니다.

### 내가 고친 노트를 지키려고

제목을 고치면 연결된 파일과 앱의 주소도 맞아야 합니다. 앱은 완료 노트의 변경 여부를 확인하고 사용자가 직접 편집한 본문을 자동 덮어쓰지 않도록 합니다. 충돌이 나면 편집본을 보존한 뒤 어떤 제목·파일을 쓸지 확인하는 방식입니다.

### ‘모델이 더 크다’를 ‘내 강의에 더 좋다’로 단정하지 않으려고

기본 turbo를 유지하고 다른 모델은 시험 후 바꾸도록 했습니다. 합성음성 시험과 실제 강의의 숫자·용어·부정 표현 정확도는 다릅니다. 작은 로컬 요약 모델도 정해진 형식을 지켰다는 이유만으로 채택하지 않았습니다.

### 화면을 정리해도 기록은 버리지 않으려고

완료한 파일과 오래된 완료 작업은 접어서 보여줍니다. 접힘은 화면 정리이며 원음·노트·작업 이력 삭제가 아닙니다. 파일 이름과 표시 제목도 구분합니다. **시연용 제목 가리기는 본문·원음의 익명화가 아닙니다.** 다른 사람에게 보여줄 때는 공개 가능한 테스트 자료를 쓰세요.

### 필요한 장치만 준비하게 하려고

PC 폴더로 먼저 시작할 수 있게 하고 NAS 자동 백업을 별도 경로로 설명했습니다. NAS를 쓰더라도 Synology Drive처럼 별도 서버·팀 폴더 구성이 필요한 방식을 기본 전제로 두지 않고 기존 SMB 공유 폴더에 붙이는 흐름을 택했습니다. 여러 사람이 인터넷에서 업로드하는 공동 서비스는 이 개인용 공개본에 포함하지 않습니다.

## 8. 막혔을 때: 메시지 뜻과 다음 행동

| 보이는 문제 | 뜻 | 해볼 일 |
|---|---|---|

| FFmpeg가 없습니다 | 음성 처리 도구를 못 찾음 | 2-3 확인. 설치 후 새 터미널·설치 창에서 실행 |
| 설치 중 다운로드 오류 | 인터넷·배포처·설치 권한 문제일 수 있음 | 오류 마지막 부분 확인. 모델 폴더를 지우지 말고 같은 설치를 다시 시도 |
| metadata_errors 오류 | 전사 라이브러리와 음성 파일 라이브러리 버전이 맞지 않음 | 앱 종료 후 Install.cmd로 이 공개본의 고정 버전 조합 재설치 |
| NAS 연결 대기 | 지정한 공유 폴더를 읽을 수 없음 | 파일 탐색기에서 그 주소 열기 → Wi-Fi·전원·계정 확인 |

| 파일이 변경 중·확인 대기 | 녹음·복사가 끝나지 않았거나 안정 확인 중 | 녹음 종료·백업 완료 후 새로고침 |
| 등록된 로컬 모델을 준비하세요 | 전사 모델 등록 전 | 설치를 마치거나 `prepare-model` 실행 |
| 정리·자동 제목 AI를 먼저 설정하세요 | 전사는 준비됐지만 정리 경로 미설정 | 원문만+자동 제목 끔, 또는 6장의 API 등록 |
| 정리 AI 대기 | 크레딧·한도·연결·모델 권한 확인 필요 | Console에서 원인 확인 후 **같은 선택 작업 재시도** |
| 이전 AI 요청이 중단됐습니다 | 중복 호출을 막기 위해 자동 재호출을 멈춤 | 사용량과 결과를 확인하고 명시적으로 재시도 |
| 노트를 직접 수정해 저장 충돌 | 앱 저장 후 사용자가 본문을 고침 | 편집본을 보존하고 앱의 제목 변경을 강행하지 않기 |
| Obsidian이 안 열림 | 앱 연결 또는 보관함 위치 확인 필요 | 노트 저장 폴더에 .md가 있는지 먼저 확인하고 Obsidian에서 그 보관함 열기 |
| 브라우저 화면이 안 열림 | 실행 창 종료·포트 충돌 등 가능 | Start.cmd 창 오류 확인. 이미 다른 앱이 8767을 쓰면 아래 별도 번호 설정 |

### 실행·종료·폴더 변경

- 시작은 **Start.cmd**입니다. 로그인 자동 실행은 등록하지 않습니다.
- 브라우저 탭만 닫으면 처리가 계속될 수 있습니다. 완전히 종료하려면 작업 완료를 확인한 뒤 **실행 창에서 Ctrl+C**를 누릅니다.
- 작업 중 PC를 끄거나 절전 상태로 만들면 처리가 중단됩니다. 다시 실행했을 때 작업 상태를 확인하세요.
- 폴더를 바꾸려면 종료 후 **Install.cmd**를 다시 실행해 주소를 고릅니다. 모델은 같은 저장 위치를 재사용합니다.
- 고급 설정은 강의서랍 폴더의 터미널에서 아래처럼 합니다. 경로는 본인 것으로 바꿉니다.

```powershell
.\.venv\Scripts\python.exe cli.py configure --source "C:\Recordings" --output "C:\StudyNotes\강의서랍" --port 8876
.\.venv\Scripts\python.exe cli.py doctor
```

`doctor`는 FFmpeg·폴더 접근·모델 등록 상태를 확인합니다. 음성 본문을 전사하거나 AI를 호출하는 명령이 아닙니다.

### 선택: 원음 파일명에도 AI 제목 붙이기

기본은 **끔**입니다. NAS 이름 변경과 FolderSync 재복사 문제를 먼저 확인하려는 설정입니다. B-5를 확인하고 테스트 원음으로 시도한 뒤 켜세요. PC 폴더만 쓸 때도 다른 복사·동기화 도구가 옛 이름을 재생성하지 않는지 확인합니다.

```powershell
.\.venv\Scripts\python.exe cli.py source-rename --enable --sync-ready
```

이후 **자동 제목을 선택한 새 작업**의 원음에만 제목을 붙입니다. 음성 내용은 바꾸지 않고 이름 변경 전후 수정 시각을 확인합니다. 단방향 NAS 백업에서는 휴대폰 이름은 그대로입니다. 끄려면 다음을 실행합니다.

```powershell
.\.venv\Scripts\python.exe cli.py source-rename
```

## 9. 무엇이 어디에 저장되나요?

| 항목 | 저장 위치 |
|---|---|
| 원음 | 내가 지정한 PC 또는 NAS 녹음 폴더 |
| 전사·정리 노트 | 내가 지정한 노트 폴더. Obsidian 안이면 해당 보관함에 표시 |
| 설정·작업 목록·전사 구간·AI 응답·키 | Windows `%LOCALAPPDATA%\LectureDrawer` |
| 프로그램·실행 환경 | ZIP을 푼 폴더와 그 안 `.venv` |
| 전사 모델 | `%LOCALAPPDATA%\LectureDrawer\models` |

`%LOCALAPPDATA%\LectureDrawer`는 파일 탐색기 주소 표시줄에 붙여넣어 열 수 있습니다. 작업 폴더에는 개인 전사와 응답도 남으므로 다른 사람에게 통째로 보내지 마세요. API 키 파일은 로컬에 보관하며 별도 암호화 금고는 아닙니다. PC 계정과 폴더 접근권한을 관리하세요.

공개 저장소에는 작성자의 녹음·전사·노트·계정 키·NAS 정보·개인 설정·세션로그·작업 DB를 넣지 않았습니다. 코드의 가상 테스트는 실제 녹음이 아닙니다. 원래 Git 이력도 가져오지 않고 별도 이력으로 시작했습니다.

## 10. 확인한 범위와 개발자용 명령

2026-11-16에 별도 Python 3.12 실행 환경 설치, 라이브러리 충돌 확인, 자동 검사 **133개**, 빈 설정에서 화면·사용법·템플릿·폰트 열기를 확인했습니다. 합성 테스트 음성의 실제 로컬 전사 → 노트 저장 → Obsidian 링크 생성도 확인했고 원음의 내용이 그대로인지 대조했습니다.

처음 새 환경을 시험할 때 faster-whisper 1.2.1과 PyAV 19의 `metadata_errors` 호환성 오류가 나서, 실제 전사에 성공한 PyAV 18.1.0 등 주요 버전을 설치 목록에 고정했습니다. 이 오류를 다시 잡을 수 있도록 모델 없이 음성 파일을 실제로 여는 검사도 추가했습니다. 그래서 설치 목록을 무시하고 라이브러리만 따로 최신 버전으로 바꾸지 않는 편이 좋습니다.

API 연결은 가짜 응답으로 요청 형식·키 분리·실패 처리를 시험했습니다. 실제 제공자로 테스트 녹음을 보내 유료 정리를 실행한 것은 아닙니다. 새 PC의 NAS·휴대폰 예약·본인 API 권한은 위 단계의 테스트로 확인하세요. 개발 PC의 확인 결과를 모든 PC의 설치 성공으로 대신하지 않습니다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

NVIDIA GPU 사용은 선택입니다. 현재 faster-whisper가 요구하는 CUDA·cuDNN 조합을 [공식 설치 안내](https://github.com/SYSTRAN/faster-whisper#gpu)에 맞춘 뒤, CPU 전사를 완료하고 GPU 구성을 별도로 검증하세요. GPU를 기본값으로 강요하지 않습니다.

이 사용법은 기존 작업기록·설계 문서·API 연결 세션 기록에서 결정 이유를 확인해 공개용으로 다시 썼습니다. 개인 원기록과 음성 내용은 배포하지 않습니다. 구독 혜택은 공식 자료로 재확인했고, 사용자의 실제 계정에 혜택이 표시되는지는 해당 계정에서 확인해야 합니다.
